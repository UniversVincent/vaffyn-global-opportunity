# Security Policy

## Supported Version

Only the latest commit on `main` is considered for security fixes during the early preview. There is no production support guarantee yet.

## Reporting a Vulnerability

Use the repository's private GitHub Security Advisory reporting flow. Do not open a public issue containing credentials, personal data, a working exploit, or private infrastructure details.

Include the affected path, impact, reproduction steps, and a minimal proof of concept with all secrets and user data removed. The maintainer will acknowledge a valid report when it has been reviewed, but no fixed response-time commitment is offered at this stage.

## Sensitive Areas

Reports involving authentication, quota bypass, profile isolation, document parsing, source-fetch SSRF, export rights, or accidental disclosure of provider credentials are especially important.

This repository contains no bug bounty program and does not authorize testing against third-party services or the public preview in a way that could affect other users.
